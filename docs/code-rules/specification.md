# Specification Source Rules

## 단일 원본

TOMO의 요구사항, 기능, 화면, 서비스 정책과 API 계약은 아래 Notion 문서를 기준 원본으로 관리합니다.

| 기준 문서 | 원본 링크 |
| --- | --- |

| 요구사항 정의서 | [Notion](https://app.notion.com/p/1-0-1-3ee3d00a28ec8011a0f5d6ddded844a3?v=5d03d00a28ec838e81f10846f8f4e4b1&source=copy_link) |
| IA | [Notion](https://app.notion.com/p/1-0-1-3ef3d00a28ec80b3924cc4098c18bc8a?v=ee83d00a28ec8352a68408f866948bf5&source=copy_link) |
| 서비스 정책 | [Notion](https://app.notion.com/p/1-0-1-3ee3d00a28ec80ba8546eea2e440a22a?v=8103d00a28ec823d85d58811ddb94b34&source=copy_link) |
| API 명세서 | [Notion](https://app.notion.com/p/API-8023d00a28ec82288cdc81da53e19fdc?source=copy_link) |

위 링크는 사용자가 제공한 기준 원본입니다. 링크 등록만으로 최신 버전, 작성 완료 또는 개별 항목의 구현 승인 여부를 확인한 것으로 취급하지 않습니다.

## 구현 전 확인

1. 구현 대상의 기능과 연결된 요구사항을 확인합니다.
2. 서비스 정책과 IA에서 관련 동작, 제한과 화면 흐름을 확인합니다.
3. API 작업이면 요청·응답, 인증·권한, 상태 코드와 오류 계약을 확인합니다.
4. 관련 요구사항·기능·API·IA 식별자와 변경 이력을 확인합니다. 번호만 같다고 서로 다른 문서의 항목을 동일하게 취급하지 않습니다.
5. 데이터 작업이면 관련 데이터 정의를 확인합니다. 정의가 없거나 불명확한 필드·관계는 추정하지 않습니다.
6. 문서 간 충돌이나 구현에 영향을 주는 미결정 사항은 확인한 뒤 해당 부분을 구현합니다. 그 결정과 무관한 준비 작업은 진행할 수 있습니다.

## 결정상태

- 원본 문서에 결정상태 체계가 있으면 그 의미를 확인하고 따릅니다.
- 원본에 없는 `PROPOSED`, `APPROVED`, `SUPERSEDED` 같은 상태를 임의로 부여하거나 필수 조건으로 요구하지 않습니다.
- 사용자가 명시적으로 확정한 범위와 결정을 구현 기준으로 기록합니다. 링크 제공 자체를 모든 항목의 구현 승인으로 해석하지 않습니다.
- 정책이나 계약이 불명확하여 결과가 달라지는 경우에는 해당 결정을 확인합니다.

## 코드 변경 규칙

- 구현, 테스트와 리뷰 설명에 관련 요구사항·기능·API·IA 식별자가 있으면 연결합니다.
- 명세와 코드 또는 명세끼리 충돌하면 차이와 구현 영향을 알리고 계약을 임의로 바꾸지 않습니다.
- 명세에 없는 필드, 상태, 오류 코드와 업무 규칙을 추정해 추가하지 않습니다.
- Notion 문서는 사용자가 명시적으로 요청하지 않는 한 읽기 전용으로 취급합니다.
- 원본 접근이 불가능하면 그 제한을 알리고 유사한 사본을 임의로 기준으로 삼지 않습니다.
- 외부 문서를 저장소에 가져오는 경우 원본 링크, 버전과 가져온 날짜를 기록합니다.
